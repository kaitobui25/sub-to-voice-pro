SUB-TO-VOICE-PRO — BUILD ROADMAP / CURRENT MVP
=================================================

TARGET
Build the smallest reliable Chrome extension that preserves Echoly subtitle-first dubbing while:
- removing unused modes
- abstracting Translation providers/models
- abstracting TTS providers/models
- using Gemini + NovAI only as first real test providers
- delaying production UI until the core pipeline is proven stable

AGENT_GOAL.txt is the binding design contract.

GENERAL BUILD RULE
Finish each phase, run its gate, commit it, then continue.
Do not stack later work on top of a broken subtitle/audio phase.

GIT / SECRET RULES
- work only in my-sub-to-voice
- never modify ../references
- commit after each completed phase
- never force-push
- never commit API keys/tokens/cookies/generated secret config
- root .env is local-only and gitignored
- commit .env.example with:
    GEMINI_API_KEY=
    NOVAI_API_KEY=

REAL API TEST RULE
Starting at Phase 2, every phase requires a tiny real API smoke test where applicable.
Keep quota usage minimal:
- Gemini: 1–2 short lines
- NovAI TTS: one short Vietnamese sentence
- browser tests: only a short video window
- no aggressive retries
- stop once behavior is proven

Because Chrome cannot read root .env directly:
- create a small dev-only script/bridge that reads .env and generates/injects runtime test config
- generated secret-bearing config must be gitignored
- do not build production UI yet
- do not create a backend server

Suggested commit sequence:
  docs/reference-audit
  feat/mv3-subtitle-baseline
  feat/translation-provider-layer
  feat/tts-provider-layer
  feat/web-audio-dub-scheduler
  feat/session-controls
  test/browser-e2e
  fix/hardening
  chore/release-ready

------------------------------------------------------------
PHASE 5 — SESSION CONTROLS + REAL SHORT BROWSER TEST
------------------------------------------------------------

Goal:
Keep Echoly lifecycle and fix pause/resume synchronization.

Tasks:
1. single active session
2. AbortController for provider calls
3. stale-callback/session token guards
4. seek: cancel -> recompute audioOffset -> reschedule
5. pause: cancel pending dub sources and stop/suspend dub cleanly
6. resume: resume AudioContext, recompute audioOffset, reschedule
7. Stop: abort requests, cancel sources, disconnect, close AudioContext, restore volume, clear state
8. ended -> clean stop
9. YouTube SPA video change -> no old-session bleed
10. playbackRate support is isolated to the playback clock/sync/scheduler layer and reuses decoded TTS buffers on rate changes

REQUIRED REAL BROWSER TEST:
Use only a short region:
- Start
- hear 1–2 dubbed lines
- pause 5+ seconds -> no dub continues
- resume -> resync
- seek forward -> no stale audio
- seek backward -> scheduler remains valid
- Stop -> immediate silence + cleanup

  feat: add reliable subtitle-first session controls
